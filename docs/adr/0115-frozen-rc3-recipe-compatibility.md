# ADR 0115: retain the exact RC3 installation generation recipe

Status: accepted

Date: 2026-10-30 UTC

## Context

After human merge of #145, ADR 0114's next boundary is historical recipe
compatibility. The current whole-installation consumer permits a Go predecessor
only when eight generator/schema source blobs equal the target image's blobs.
This correctly refuses unknown reconstruction, but would also refuse genuine
RC3 installations after the target's generators or installation inventory change.

The published `v0.2.0-rc.3` release identifies immutable source
`95486ecdd3868a319a0e6362ee99cafd8f154200`. Its compiled selection contains
141 reviewed role rows, including 85 inert initializer-cache rows. Preserve this
closed recipe before later slices change generators or retire cache inputs.
This change grants no new filesystem ownership and executes no predecessor code.

## Closed reconstruction contract

Recognize the historical recipe only when all eight original source blobs exist
and match their independently calculated SHA-256 values from that immutable
commit: `generate.go`, `roles.go`, `orchestration.go`, `reference.go`, `model.go`,
`observe.go` and `selection.go` in `internal/installation`, plus
`internal/installedlayout/layout.go`. A version label or a filename is insufficient.
Missing or altered fingerprint members must refuse historical reconstruction.

Freeze the 141 historical role rows as compiled inert data. Use that table for
recognized historical images, including complete descriptor reconstruction with
the original file modes, hashes, deterministic ordering and serialization.
Reuse reviewed native generators and the existing selection/descriptor pipeline;
never parse or execute Go, shell, Python or arbitrary role definitions supplied
by a predecessor archive. Future generator changes must preserve the original
historical serialization and continue passing the real-RC3 reconstruction test.

Retain exact current-recipe matching as a separate supported path. Compare every
existing fingerprint member and the new selector and historical-role source
files, requiring their presence in both images and byte equality. Changes to
either new file must not silently bypass compatibility checks. A predecessor
which matches neither the current closure nor the frozen historical vector
remains an actionable preserved conflict.

Feed the reconstructed before-image through existing observation, ownership,
proposal, confirmation, backup, whole-installation transaction and rollback
controls. Preserve edited, unknown and unsafe adopter files and accounting
history. Historical recognition never authenticates an image, grants mutation
consent or permits executing its saved runtime/source as a fallback.

Keep current installation roles, initializer inventory, generated output and
command defaults unchanged in this slice. All 85 existing cache rows remain;
the later reviewed retirement boundary owns removal of the 83 obsolete rows.
Publish no new candidate and keep the stable installer pinned to v0.1.6.

## Independent qualification

An independent Ginkgo/Gomega author rebuilds the trusted immutable RC3 source
as an evaluator fixture and runs its initializer to establish a genuine prior
installation. The current consumer treats the supplied image as inert data.
Exercise explicit existing candidate/installation routes; do not depend on
unmerged default selection, public local-init or cache-retirement functions.

Observe meaningful refusal before the repair when a target declares a changed
generation fingerprint, then require exact historical reconstruction through
read-only preview, fresh-consent apply and rollback. Compare generated bytes,
modes and descriptor data against the real predecessor, and preserve custom
application files and runtime history. A changed target recipe declaration in
the evaluator is compatibility data, not proof of a released new generator.

Individually change or remove historical fingerprint members and require refusal
without executing supplied code or mutating the adopter. Cover the selector and
historical-role files in current-recipe matching. Independently compare the
frozen role data with immutable RC3 source rather than deriving the oracle from
the implementation under test.

Derive the new acceptance census from actual discovery. Give the heavy ordered
`Historical RC3 installation recipe compatibility` family its own
`historical-recipe` Linux/macOS partition, introduced with its scheduling proof.
The previous macOS handoff job ran for 20m32s on #145, close to the existing
25-minute test allowance. Exclude the new family from base; preserve the existing
installation and handoff selections. Reuse the resource-aware handoff worker
allowance, Ginkgo CLI, race instrumentation and JSON/JUnit report plumbing.
The complete default/all run must attempt all four groups and propagate each
failure. Keep exhaustive disjoint identity coverage and every quality stage;
retain the new hosted reports without raising test/job deadlines.

Fresh Linux/macOS checks, verified independent review findings, public model
review responses and exact-head hosted coverage precede human merge. This
compatibility prerequisite does not close default-cutover or release gates.
