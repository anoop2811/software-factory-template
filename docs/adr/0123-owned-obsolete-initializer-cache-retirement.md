## Ownership, preview and safe publication

Only a freshly inspected complete qualified before image that actually selected
an obsolete cache path can qualify that path. Exact content, regular type,
complete mode and safe physical ownership must match the qualified projection.
A local descriptor, journal, receipt, count, filename or equal-looking copy is
not ownership authority. A 58-row before image did not select the omitted 83;
leftovers there remain unowned and preserved even if their bytes look canonical.

Preview lists each declared retirement or preservation reason, preserves both
consumed data files, and changes no project, cache, ignore or recovery file.
An edited, unknown, missing, mode-changed, hard-linked or symlinked entry and an
unsafe ancestor are preserved. Optional obsolete-cache conflicts do not prevent
a complete new installation when its active required selection remains usable.
Required active-file conflicts retain their existing refusal behavior. Never
follow an outside referent or recursively remove an unclassified directory.

Apply retains fresh complete consent and exclusive admission. Before unlinking
any selected obsolete leaf, reuse the existing checked, locally gitignored
`.factory/backups/MIGRATION_ID/` store: exact original bytes, original path and
restore metadata, stored as inert 0600 data under 0700 private directories.
A stale preview, backup/ignore failure or uncertain process/file ownership must
not authorize deletion. Repeat application and a second cleanup perform no
additional retirements or hidden recovery expiry.

## Reverse, recovery and retention

Retain the original generation of every journal, manifest and receipt. Recognize
complete 58-row and 141-row closed path sets for parsing, then bind all mutation
authority to fresh qualified source/before images. The new 141-row retirement
set has the same path set as the historical 141-row active-cache generation;
its count or membership alone cannot select either generation or action labels.
Do not rewrite old records into the newest shape.

An actually retired canonical cache leaf must be restored from its independently
qualified inert saved original, with the original mode, before the historical
85-cache descriptor can activate. Preserve later edits and refuse stale or
unqualified saved data before any reverse publication.

A preserved optional retirement still may be required by the historical target.
During reverse qualification, exclude rows with both target Operation retire
and original Action retain from the set considered covered by the transition.
Reuse the existing preserved-predecessor check to block an old required cache
that remains edited, missing or unsafe. Actually retired rows are covered only
after existing canonical-before, saved-data and reverse-action checks succeed.
Do not turn a retained custom cache into a canonical archive overwrite merely
to make the old descriptor usable.

Existing interruption, preparation abandonment, pending barriers, durable
publication and compiler-free recovery remain the transaction owner. Preserve
all process/readiness and recovery-evidence custody guarantees. Retention still
qualifies actual complete before/after images and saved canonical files before
pruning; a retained/missing required historical cache cannot prove a usable
alternate. Local/unversioned builds, equal versions, rollback, failed checks and
pending operations do not advance expiry. No retention-policy change belongs here.

## Review refinement: retained unsafe rows and incomplete retirement evidence

An unchanged unsafe optional cache entry that forward application deliberately
retained remains outside mutation authority during completed forward replay,
committed-pending cleanup and unchanged preparation abandonment. Those no-write
paths must not fail merely by treating that irrelevant leaf as a mutable selected
asset. Continue every fresh image, active-installation, journal/check ownership,
parent/root identity and pending-marker check that actually authorizes work.
Reverse activation of an old image that requires that unsafe cache still refuses.

A record's retire label is not evidence that an original existed or was saved.
If a required historical cache row has Before null, it cannot count as reverse
coverage without the independent canonical-before and saved-original proof.
Coherently changing both journal and manifest cannot grant that proof. Refuse
an unqualified reverse proposal before any old descriptor or active file changes;
the current final installed validation is not a substitute for preflight refusal.

Independently observe both controls before further repair: real forward-retained
symlink/hardlink replay, actual committed-pending and prepared evidence created
by an evaluator-only save boundary, and a genuine retired row with Before cleared
in both records while keeping retire labels. Keep the existing valid rollback
positive control and full unchanged-tree/outside-referent assertions. Add no
shipping test seam, broad skip or relaxed owned-path/identity check.
