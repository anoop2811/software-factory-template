# ADR 0147: preview existing-project CI migration without mutation

Status: implemented; independent local qualification passes. Hosted qualification is pending.
Decision: 163. Continues R4 after merged PR #177.

## Boundary

PR #177 merged as `8f2c6ae27f47a1ddbffc76cc10bdceffd424f2c4` on
2026-11-10 UTC. New authenticated projects have ordinary installed-runtime CI.
Existing projects still retain their copied development/pack workflows. First
make their ownership and proposed replacement visible in the existing upgrade
preview; a following bounded change will integrate the proven projection into
backup, activation, interrupted recovery, rollback and retention.

This is read-only planning, not workflow migration. Do not change transactional
Actions, confirmation digests, frozen recipes, runtime descriptors, installation
Selection, backup schemas, or apply behavior. Do not add a command or flag. A
workflow customization must not become a runtime-admission requirement. Keep
optional review-lane bootstrap and the hosted adopter rehearsal separate.

## Public report

For an authenticated ordinary or explicit candidate upgrade preview, add a
`ci_workflow` object to its existing JSON envelope and a clearly labeled text
section. The release owner supplies the authenticated target tag, full revision,
origin platform and official repository explicitly. Inspection metadata,
`Candidate`, a local label or an environment variable alone is not authentication.
Do not manufacture a downloadable release for local-source or noncanonical tags.

The object has `schema_version: 1`, `mode: "ci-workflow-preview"`,
`apply_supported: false`, `changes`, `conflicts` and a human-readable `reason`.
Each change names `path`, `disposition` and `reason`; dispositions are `create`,
`replace`, `retire`, `preserve` or `absent`. Include before/after SHA256 values
where independently available, with no runtime identity, custody or deletion
authority implied. Always explain that confirmation currently applies only to
the existing installation actions and does not perform these proposed CI changes.
Keep CI conflicts distinct from existing runtime blockers and exit semantics.
No result may claim the project is ready for installed CI or for release.

The report is an informational snapshot, excluded from consent. It is not read
back as a plan, journal or ownership receipt. The following apply change must
reconstruct and bind its own exact observations before mutation. Operational
read/cancellation/output failures remain errors rather than successful unknown
results. Local-source and ineligible release previews explicitly explain why an
authenticated CI proposal is unavailable, without network lookups to invent one.

## Finite ownership and preservation

Inspect only `.github/workflows/ci.yml`, `go-pack.yml`, `typescript-pack.yml`,
`java-pack.yml` and `factory.yml`. Other application and optional review workflows
are outside this selection and remain unread and untouched. Observe through the
existing bounded, no-follow filesystem machinery and recheck the read-only lease.
Directories, links, special files, mode changes and oversized entries are preserved
and reported as conflicts; do not follow or execute them.

Recognize copied legacy workflows only by exact bytes and mode reconstructed
from the independently pinned v0.1.6 or Bash-baseline catalog and a closed
initializer projection. Map each installed pack filename to its actual source
template; Java Maven and Gradle have distinct sources. Do not infer installation
from the mere presence of a workflow in a source catalog. Missing legacy paths
are absent, not failures. A present unselected pack workflow is a conflict.

For Go predecessors, use the independently qualified predecessor image and an
explicitly supported initializer/renderer recipe. Authenticating an arbitrary
source archive does not qualify its initializer transformation. Unknown recipes
remain preserved. Reconstruct old generated `factory.yml` from its old qualified
release selectors and renderer, never from new pins or a header alone. Matching
old generated bytes are replaceable by the target rendering; custom bytes remain
preserved/conflicted. Retain frozen renderer evidence when its implementation
changes; comparing with today's implementation alone is insufficient.

An absent `factory.yml` proposes creation. Any unresolved known-path occupant
prevents a claim of an applicable whole-workflow migration: never suggest that
adding a new job alone repairs old broken jobs. Report every relevant conflict,
while preserving a useful per-path classification. All proposed new workflow
bytes come from the existing pure initialized-workflow renderer with the exact
authenticated target identity. Do not duplicate the bootstrap or tool catalog.

## Project inputs

Read one bounded no-follow `factory.yaml` snapshot. Validate selected keys before
extracting flat values: reject ambiguous duplicates, invalid Unicode/NUL,
unsupported packs, missing selected language versions, invalid Java build choice
and unsupported multi-path mutation inputs. Preserve the existing generic project
input/override contract. Do not silently choose current defaults for old projects.
Settings changed since initialization may prevent exact recognition; that is a
preservation conflict, not permission to rewrite customized CI.

Support the existing Go, TypeScript and Java selections and combinations. Reuse
the current application renderer input shape. Reconstruct historical version,
protected-path and mutation substitutions conservatively; unsupported historical
sed replacement syntax is unrecognized. Because Maven command choice was not
persisted separately, recognize only exact closed `mvn` and `./mvnw` projections,
without executing a wrapper. No external tools, model calls or new dependencies
are necessary for planning.

## Independent qualification

Observe Ginkgo/Gomega RED before production changes. Use independently read
immutable Git/catalog bytes or literal semantic expectations as the oracle,
not the planner's own generator. Cover all pack/Java combinations, absent and
exact copied workflows, generated-workflow refresh using old selectors, changed
settings, customized/unsafe/mode-changed occupants, malformed inputs, unknown
recipes, local/noncanonical release boundaries and operational failures.

Exercise the real public upgrade preview in both JSON and text form with its
authenticated release handoff. Assert that runtime Actions, proposal digest,
existing exit behavior and confirmation advice retain their meaning. Snapshot
project files, Git HEAD/index/status and private state before/after preview;
prove no workflow, recovery set or installation state is created or modified.
Keep these assertions independent of output substring matches alone.

Run focused race qualification, configured lint and the existing affected preview
regressions in complete private checkouts. Preserve the operator's ignored binary
and unrelated files. Follow the review-diamond graph before publishing. Hosted
CI, transactional apply, optional review bootstrap and release qualification
remain separate evidence; do not count this preview as completed migration.

## Closed historical projection

Qualify copied Go initialization against immutable source
`6b8f08c820c347a9c9d12c4afd00b3f7e6aca547` and generated initialization against
`8f2c6ae27f47a1ddbffc76cc10bdceffd424f2c4`. Bind every production Go source in
the relevant initializer/inventory namespaces; generated initialization also
binds its workflow-renderer sources. An added source file in those namespaces
invalidates that closed recipe, just as changed bytes do. Other unqualified
predecessors remain preserved with a specific explanation.

For the generated historical recipe, read only inert string constants from the
qualified old image and reproduce that recipe's fixed composition. Never execute
old source, invoke a compiler, or load template code from the adopter's worktree.
The current renderer remains the single source of proposed target workflow bytes.
This permits later target pin updates without reinterpreting the old workflow
through new constants. No hashes computed from the current worktree establish
historical authority.

Current application settings and historical reconstruction inputs have different
purposes. Validate and render target application setup from the observed current
configuration. Existing `--project-input` values may supply historical generic
substitutions for recognizing old files; they must not mask malformed current
settings or silently choose a different target mutation directory.

Review refinement: both pinned Bash initializers' `mutation_target` functions
use every nonempty protected path literally. A dot input therefore produces
`././...`, while an empty input produces `./...`. The general installation
substitution helper normalizes dot differently and cannot qualify these workflow
bytes. Preserve the actual historical initializer distinction in this preview's
closed projection, including a negative control for manually normalized bytes;
do not modify a frozen runtime recipe to achieve it. Missing pack-selection or
protected-path keys are unknown inputs, not proof of an empty selection/path.

Historical Go substitutions must satisfy the relevant frozen initializer's input
validation. A generic override containing a parent traversal, absolute protected
path, forbidden character or unrepresentable scalar cannot establish ownership
of a workflow that the old initializer could not produce. Decline that historical
projection and preserve the occupant, while keeping valid current target setup
and the existing generic runtime override interface unchanged. Test a valid old
path override separately from these impossible-history controls.

## Hosted review refinement

The first hosted review covered all 17 files and 25 fragments in two batches,
finishing in 2m19s. Strengthen the frozen generated-workflow oracle with a literal
golden captured by executing the actual renderer from immutable
`8f2c6ae27f47a1ddbffc76cc10bdceffd424f2c4` in a complete private qualification
checkout. Use the existing all-pack Gradle case and fixed old release selectors.
The saved bytes must agree with the independent matrix oracle; they must not be
generated by the current renderer or by another manual reassembly. This is test
qualification only; the installed planner continues to treat old source as inert
data and never executes it. Keep production behavior and existing criteria intact.

Further full-source verification identifies one omitted historical Go constraint:
`PROJECT_SLUG` and `DOCS_ROOT` must round-trip losslessly through the old flat
reader, with empty docs mapping to `docs`. A permitted marker-valued version can
expose a later generic substitution; a historical docs override such as
`docs #tail` must not qualify copied bytes because the old initializer rejects
its truncation to `docs`. Preserve valid `docs#tail`. Add an independent positive
and impossible-scalar control, then complete the historical-only validation.
