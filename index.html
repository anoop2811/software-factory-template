v0.2.1 Stable release

Your repo, ready for coding agents.

A new repo can mean wiring up tests, CI and instructions for each coding agent by hand. Software AI Factory bootstraps that setup in a new or existing project. Codex, Claude Code and OpenCode share the project’s roles and checks, and you choose when to spend tokens on review or repair.

What you get in your repo.

A Go service and a TypeScript frontend need different tools. They can still share one project configuration, one set of agent roles and one command to run the checks.

Bootstrap the project

Run the initializer and choose Go, TypeScript, Java, a combination, or the core factory alone. It writes factory.yaml, installs the selected pack files and generates a GitHub Actions workflow for authenticated release installs. You supply the application and its tests. Set up a project.

Switch coding agents

Move from writing a spec in Claude Code to implementing it in Codex or reviewing it in OpenCode. The factory ships five role definitions and generates each harness’s configuration from the same source. After changing roles or model settings, run ./factory sync all. Configure roles and models.

Catch a mistake before merge

Configure ./factory check to run your project’s checks. For example, the edit hook can block an implementer from changing a matching test file. The generated CI also checks harness wiring and runs a mock evaluation on pull requests. See which checks run where.

Find out what actually ran

Use ./factory doctor to find an inactive gate or a missing adapter. Use ./factory metrics --json to inspect local block and rework signals. When an enabled agent run reports usage, ./factory budget report shows it. Read your project metrics.

Review a change in context

Use the spec template and role-based review recipe to take one behavior from requirement to reviewed PR. Enable advisory review to ask a configured model to inspect same-repository PRs targeting the default branch. These reviews can use paid tokens. Set up PR review.

Upgrade an existing factory

Preview which files will change before moving a supported v0.1.6 installation to Go. The installer identifies conflicts, requires confirmation and keeps a local recovery backup. Your team can carry on using ./factory. Walk through an upgrade.

Set limits before an agent runs.

Start with a local plan. To launch an agent through factory budget run, enable the budget and use your configured harness CLI and credentials.

factory budget

Limit attempts and runtime

Limit task attempts, session runs, execution time, and concurrent factory invocations. Preview the plan locally before enabling a run. An optional threshold uses estimated cost to warn or stop later launches. A single invocation can exceed that estimate. Choose your budget controls →

factory budget report

Inspect each attempt

The local ledger records the harness, role, duration and outcome of factory-managed attempts. Reports show token usage or cost estimates when available and mark missing values as unknown. The ledger omits prompt and response bodies. Your harness controls its own history. Explore run reporting →

factory loop

Choose when to retry

In manual mode the factory runs your configured check once. The factory itself makes no model call in this mode. In bounded mode, the factory runs the implementer, checks the changes and calls a separate reviewer after checks pass. Repair attempts share the budget and stop at the configured limits. Configure a bounded loop →

Keep a pull request reviewable

The project recommends shipping one change in behavior with its tests, compatibility work and documentation. For model-assisted PR review, the optional review lane can split a diff into batches with request and token limits. Plan reviewable changes →

Try the local plan and report commands 
# shows a blocker (exit 2) while budget_enabled is false
$ ./factory budget plan --harness codex --session demo --task first

# inspect local run history
$ ./factory budget report --session demo --json

# in a committed Git project with a configured check command
$ ./factory loop plan --harness codex --session demo --task first

For either plan, select codex, claude or opencode. One budgeted attempt is one factory-managed CLI launch. Bounded loops require loop_enabled and budget_enabled. Allow for reviewer calls in the budget.

Install v0.2.1 in your project.

Run these commands from the project directory. The installer uses Git, Bash and an authenticated GitHub CLI. Check gh auth status first. The packaged Go CLI needs neither a Go compiler nor Python to initialize a new project. Project builds, retained hooks and coding harnesses have their own prerequisites.

New project

curl -fsSL https://softwareaifactory.sh/install.sh | sh -s -- init --ref v0.2.1 --pack go

Preview a v0.1.6 upgrade

curl -fsSL https://softwareaifactory.sh/install.sh | sh -s -- upgrade --ref v0.2.1 --dry-run --json

Confirm the reviewed upgrade

Pause other factory work and replace PROPOSAL_DIGEST with the digest from your preview.

curl -fsSL https://softwareaifactory.sh/install.sh | sh -s -- upgrade --ref v0.2.1 --confirm PROPOSAL_DIGEST --quiescent

The preview reports file actions and blockers. Modified or unrecognized factory files can block automatic migration. A confirmed upgrade retains a Git-ignored local recovery backup. Existing v0.1.6 projects choose when to migrate. Upgrade and recovery guide.

What’s next?

Today v0.2.1 ships workflow recipes for review and evaluation. The following proposals are planned work beyond this release.

Context and memory

Task-specific context selection, searchable project memory and handoffs with source references.

Harness and graph engineering

Capability probes, isolated execution and resumable workflows with explicit handoffs.

Repository retrieval and MCP

Cited retrieval over code and specs, and a catalog of tools with configurable permissions and output limits.
